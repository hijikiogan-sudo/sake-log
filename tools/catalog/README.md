# 商品辞書（バーコード）の更新

`beer-save/beer-catalog.js` は、バーコードを読んだときに銘柄・容量・度数を出すための辞書です。
このフォルダのスクリプトで、各メーカーの公式サイトから集め直して更新します。

## 実行のしかた

リポジトリのいちばん上のフォルダで実行します。Python 3.9 以降があれば動きます（追加のインストールは不要です）。

```bash
python3 tools/catalog/update_catalog.py --dry-run
```

まず `--dry-run` で、追加・変更される商品を確認します（ファイルは書き換えません）。問題がなければ、`--dry-run` を外して実行します。

```bash
python3 tools/catalog/update_catalog.py
```

| オプション | 内容 |
|---|---|
| `--dry-run` | 結果を表示するだけで、辞書は書き換えない |
| `--only asahi,kirin` | 指定したメーカーだけ集める（asahi / kirin / takara。sapporo は指定したときだけ動く） |
| `--cache フォルダ` | 取得したページを保存し、2回目以降はサイトにアクセスしない（調整用） |
| `--report ファイル.json` | 追加・変更・見つからなかった商品を JSON で書き出す |
| `--summary ファイル.md` | 結果の要約を日本語の Markdown で書き出す（PR の本文に使う） |

全メーカーで数十分かかります。サイトに負担をかけないよう、同じサイトへのアクセスは1.5秒以上あけています。

## 毎月の自動実行（GitHub Actions）

毎月1日の9時（日本時間）に、GitHub Actions がこのスクリプトを実行します。商品の追加や値の変更があったときだけ、開発ブランチ向けのPR（商品辞書の更新）を作ります。

- ワークフローのファイルは **gh-pages ブランチ**の `.github/workflows/update-catalog.yml` にあります。GitHub の毎月の自動実行は既定ブランチ（このリポジトリでは gh-pages）にあるファイルでしか動かないためです
- GitHub の Actions 画面で「Update barcode catalog」→「Run workflow」を押せば、すぐに実行することもできます
- PR をマージしても公開はされません。公開（gh-pages への反映）は別に行います
- リポジトリ設定の「Allow GitHub Actions to create and approve pull requests」が有効になっている必要があります

新商品の発売が多い時期（春・秋）は、手で実行してもかまいません。

## 辞書の更新ルール

アプリは、利用者が保存した商品と辞書の商品を「JAN・商品名・容量・度数・`revision`」で同じものと判断します（`beer-save/beer-recognition.js` の `pool`）。カロリーと分類は判断に使わず、保存済み商品のカロリーが空欄のときだけ、候補の表示に辞書の値を補います。そのため、次のように更新します。

- 容量・度数が前回と同じ商品は、商品名・`revision` を**書き換えない**
- 容量・度数が変わった商品は「仕様変更」として、値と `revision`（`公式情報確認 日付`）を更新する。保存済みの人には新旧2つの候補が出て、缶の表示で選んでもらう
- カロリーは、空欄なら埋め、変わっていれば更新する。`revision` は変えない
- 新しい JAN は末尾に追加する
- 今回見つからなかった商品は**消さない**（終売品の缶を読む人がいるため）
- 取得できなかったメーカーの商品は、前回の内容のまま残す

商品名・別名（aliases）・除外語（excludeTokens）・OCR 用の別名は、人が手で整えた値を残します。
新しく追加する商品の別名は「商品名」と「商品名からメーカー名を外したもの」だけにします。写真の文字読み取りは別名を含むかで探すため、「贅沢搾り」のようなシリーズ名だけを別名にすると、どの味を撮っても同じ商品が候補に出てしまいます。

## 自動で集められないメーカー

| メーカー | 理由 | 対応 |
|---|---|---|
| サントリー | 公式の商品ページが自動アクセスを拒否する（HTTP 403） | 既存の内容を維持。追加は手作業 |
| サンガリア | JAN が画像の PDF にしか載っていない | 既存の内容を維持。追加は手作業 |
| サッポロビール | 公式サイトに JAN が載っていない（容量・度数・カロリーは載っている） | 既存の内容を維持。公式サイトが JAN を載せ始めたら `sources/sapporo.py` がそのまま拾う（`--only sapporo --dry-run` で確認） |

アクセスを拒否するサイトに対して、ブラウザを装うなどの回避はしません。

## 更新したあと

1. `git diff --stat` で、`beer-save/beer-catalog.js` だけが変わっていることを確認する
2. 追加された商品を何件か、公式ページと見比べる
3. アプリで「設定 → 商品辞書について」の件数と確認日が変わったことを確認する
4. コミットする。公開（gh-pages への反映）は別途確認してから行う

Web 版は、公開後に次に開いたときから新しい辞書を使います（ブラウザのキャッシュにより最大10分ほど遅れることがあります）。アプリの JS を変えたときは、必ず版番号も上げてください。読み込み URL の `?v=` が同じだと、ブラウザが古い JS を使い続けます。版番号は、`beer-save/index.html`・`beer-save/log.html` の `?v=`、`beer-save/sw.js` の `CACHE`、`beer-save/kanlog-maintenance.js` の `VERSION`、`beer-save/kanlog-release.json` の5か所をそろえて上げます（ホームの「新しい版」のお知らせもこれで出ます）。iOS 版は辞書をアプリ内に持つため、アプリを作り直して配布する必要があります。

## ファイル

- `update_catalog.py` … 全体の流れ（収集 → 統合 → 書き出し）
- `common.py` … ページ取得（robots.txt の確認・間隔あけ）と共通の処理
- `sources/*.py` … メーカーごとの読み取り処理。サイトの作りが変わったら、ここを直す
